## 3. 인증 설계

| 토큰 | 유효기간 | 저장 위치 |
|------|----------|-----------|
| Access Token | 1시간 | 메모리 (Zustand) |
| Refresh Token | 7일 | httpOnly Cookie + DB(users.refreshToken) |

Access Token 만료 시 Refresh Token으로 자동 재발급하고, Refresh Token도 만료되면 재로그인을 요구한다. 토큰 갱신 실패 시 `Promise.reject()`로 에러를 전파하여 호출부에서 정상적으로 catch할 수 있도록 한다.

### 역할별 Guard

```
STUDENT    → JwtAuthGuard
INSTRUCTOR → JwtAuthGuard
ADMIN      → JwtAuthGuard + RolesGuard(ADMIN)
```

## 4. 강의 상태 흐름

```
DRAFT ──→ PENDING ──→ APPROVED
  ↑              └──→ REJECTED
  └─────────────────────┘
```

- 강사가 DRAFT 상태로 초안 생성
- 심의 신청(submit) → PENDING
- 관리자 승인 → APPROVED (수강생에게 공개)
- 관리자 반려 → REJECTED (강사가 수정 후 재신청 가능)

## 5. YouTube 영상 연동 흐름

1. 강사가 강의 단위 등록 시 YouTube URL 입력
2. 서버에서 Video ID 파싱 — 유효하지 않으면 `400 BadRequestException` throw
3. 지원 URL 형식: `youtube.com/watch?v=`, `youtu.be/`, `youtube.com/embed/`
4. 파싱된 Video ID를 `youtubeVideoId` 컬럼에 저장
5. 프론트에서 IFrame API로 임베드 재생
6. `onStateChange === YT.PlayerState.ENDED` 감지
7. `POST /progress/complete` 호출 → 진도율 업데이트

## 6. 보안 설계

### Rate Limiting

| 엔드포인트 | 제한 | 이유 |
|-----------|------|------|
| 전역 | 60회/분 | 일반 API 남용 방지 |
| POST `/auth/login` | 10회/분 | 브루트포스 공격 방어 |
| POST `/auth/register` | 5회/시간 | 대량 계정 생성 방지 |

프록시 뒤에서도 실제 클라이언트 IP 추출을 위해 `ThrottlerBehindProxyGuard`를 사용한다 (`X-Forwarded-For` 헤더 우선).

### HTTP 보안 헤더 (Helmet)

| 헤더 | 효과 |
|------|------|
| `X-Powered-By` 제거 | 프레임워크/버전 정보 노출 차단 |
| `X-Content-Type-Options: nosniff` | MIME 스니핑 방지 |
| `X-Frame-Options: SAMEORIGIN` | 클릭재킹 방지 |
| `Strict-Transport-Security` | HTTPS 강제 |

## 7. 주요 설계 결정

| 항목 | 결정 | 이유 |
|------|------|------|
| 수강 신청 | `upsert` 사용 | `findUnique + create` 레이스 컨디션 방지 |
| 리뷰 평균 평점 | `aggregate` 전체 기준 계산 | 페이지 단위 계산 시 부정확한 평균 문제 |
| 어드민 라우트 보호 | 렌더 시점 `<Navigate>` | `useEffect` 방식의 UI 플래시 방지 |
| AuthUser 타입 | `import type` 사용 | `emitDecoratorMetadata` + `isolatedModules` 조합에서 TS1272 오류 방지 |
| Refresh Token 저장 | `users.refreshToken` 컬럼 | 별도 테이블 없이 단순하게 관리 |
