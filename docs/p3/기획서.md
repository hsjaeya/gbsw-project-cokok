# 기획서

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 프로젝트명 | COKOK (cook of king of king) |
| 버전 | v3.0 |
| 서비스 유형 | 요리 온라인 강의 플랫폼 |
| 목표 | 외부 연동·운영 관측성·보안 강화·결제 모듈을 갖춘 프로덕션 수준 플랫폼 구축 |
| 타겟 사용자 | 요리를 배우려는 일반인, 강의를 등록하려는 강사 |

---

## 2. 서비스 배경 및 목적

p2에서 구축한 심의 시스템과 리뷰 기능을 기반으로, 실제 서비스 운영에 필요한 요소를 추가한다. 이메일·디스코드 구독 알림, 스케쥴러 기반 배치 작업, Webhook 연동, 결제 모듈, 보안 강화(SQL 인젝션·XSS), 코드 최적화 및 모니터링 시스템을 도입하여 프로덕션 수준의 플랫폼으로 발전시킨다.

---

## 3. 사용자 역할

| 역할 | 설명 |
|------|------|
| STUDENT | 강의 탐색, 수강, 결제, 이메일 구독, 알림 수신 |
| INSTRUCTOR | 강의 관리, 심의 신청, Webhook 수신(승인/반려 알림) |
| ADMIN | 강의 심의, 카테고리 관리, 회원 조회, 시스템 로그 조회, 배치 실행 |

---

## 4. 핵심 기능

### 4.1 구독 (이메일 / 디스코드)

| 기능 | 설명 |
|------|------|
| 이메일 구독 | 신규 강의 승인 시 구독자에게 이메일 발송 |
| 디스코드 구독 | 디스코드 Webhook URL 등록 후 알림 수신 |
| 구독 해지 | 구독 취소 처리 |

### 4.2 스케쥴러

| 기능 | 설명 |
|------|------|
| 주간 강의 요약 메일 | 매주 월요일 인기 강의 Top 5를 구독자에게 발송 |
| 미완료 수강 알림 | 7일 이상 진도가 없는 수강생에게 독려 이메일 발송 |
| 만료 데이터 정리 | 30일 이상 된 로그 데이터 자동 삭제 |

### 4.3 Webhook

| 기능 | 설명 |
|------|------|
| 강의 심의 결과 알림 | 승인/반려 시 강사의 등록 Webhook URL로 POST 요청 |
| Webhook 로그 | 발송 이력 및 응답 상태 저장 |

### 4.4 결제 모듈

| 기능 | 설명 |
|------|------|
| 강의 결제 | 토스페이먼츠 연동으로 강의 유료 구매 |
| 결제 확인 | 결제 완료 후 서버에서 검증 및 수강 이력 생성 |
| 결제 내역 조회 | 마이페이지에서 결제 내역 확인 |
| 환불 | 관리자 또는 사용자가 환불 요청 처리 |

### 4.5 보안 강화

| 기능 | 설명 |
|------|------|
| SQL 인젝션 방어 | Prisma ORM 파라미터 바인딩 + raw query 사용 금지 정책 |
| XSS 방어 | 입력값 sanitization, CSP 헤더 설정 |
| 감사 로그 | 관리자 주요 작업(승인/반려/삭제) 로그 기록 |

### 4.6 모니터링 및 운영 로그

| 기능 | 설명 |
|------|------|
| 구조화된 로그 | Winston 기반 JSON 로그 출력 |
| 헬스체크 | `/health` 엔드포인트로 서버 및 DB 상태 확인 |
| API 응답 시간 측정 | 인터셉터로 요청별 처리 시간 로깅 |

### 4.7 코드 최적화 / 성능 향상

| 기능 | 설명 |
|------|------|
| DB 인덱스 추가 | 강의 목록 조회 쿼리 최적화 |
| N+1 쿼리 제거 | Prisma include 최적화 |
| 프론트 렌더링 최적화 | React.memo, useMemo, 코드 스플리팅 적용 |
| 이미지 최적화 | 썸네일 lazy loading 적용 |

## 5. 결제 흐름

```
사용자 [결제 요청]
  → 프론트에서 토스페이먼츠 결제창 호출
  → 결제 완료 후 서버로 결제 키 전달
  → 서버에서 토스페이먼츠 API로 결제 검증
  → 검증 성공 → payments 테이블 저장 + 수강 이력 생성
  → 검증 실패 → 결제 취소 처리
```

---

## 6. 알림 발송 흐름

```
이벤트 발생 (강의 승인 / 주간 요약 등)
  → 스케쥴러 또는 이벤트 트리거
  → 구독 테이블에서 대상 조회
  → 이메일(Nodemailer) / 디스코드(Webhook) 발송
  → 발송 결과 로그 저장
```
